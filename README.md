# Portfolio Jay Designer

Create a professional bilingual portfolio website for Jay Farfan, a Senior Product Designer.

The goal of the website is to position Jay as a creative, strategic, technical, reliable Senior Product Designer with leadership potential, without explicitly presenting him as a “Lead”. The portfolio should communicate that Jay solves complex problems by combining strategy, human judgment, and artificial intelligence.

The site must support two languages:

- Spanish version: default.

- English version: activated through a simple ESP / ENG language selector.

- The UI should allow switching between Spanish and English.

- All main content must exist in both Spanish and English.

GENERAL VISUAL DIRECTION

Use a dark mode, monochromatic, premium and editorial visual style.

Visual references:

- Use Gianmarco Ramos’ portfolio as inspiration for bold typography, strong project presentation and color usage per project.

- Use Marcos Rezende’s portfolio as inspiration for a more editorial, senior, horizontally scannable project structure.

- Do not copy these websites exactly. Use them as strategic visual references.

Style requirements:

- Main background: black or very dark gray.

- Typography: large, clean, modern and bold.

- Base colors: black, white, gray.

- Use color mainly in the project banners/cards.

- Avoid using a large portrait photo in the hero.

- Do not make the site look like a generic startup landing page.

- Do not make it look overly futuristic or “AI gimmicky”.

- The website should feel senior, strategic, modern, clear and trustworthy.

HERO ANIMATION

Add a very subtle secondary animation in the hero background:

- Abstract network of thin nodes and lines.

- Slow movement.

- Represents the connection between users, business, technology and artificial intelligence.

- Must not distract from the text.

- Maintain strong contrast and readability.

SECTION 2 — SELECTED WORK

This section appears immediately after the hero.

Design the projects as horizontal banners, not full-screen sections.

Each project banner should include:

- Project number

- Label: CASE STUDY

- Title

- Short description

- Tags

- A visual area on the right side for a project illustration

- Distinct background color or accent color

- CTA button: “Ver caso” in Spanish / “View case study” in English

- Some projects can be marked as “Próximamente / Coming soon” if the case study is not developed yet.

The banners should be large and visually strong, but compact enough that several projects can be discovered naturally while scrolling.

PROJECT VISUALS / ILLUSTRATIONS

Each project banner must include a dedicated visual area on the right side.

For now, generate provisional project illustrations that match the nature of each project. These are placeholder visuals that help the portfolio feel complete before final assets are available.

The provisional illustrations can include:

- phone mockups

- laptop / desktop mockups

- dashboard screens

- charts / diagrams

- abstract product-related graphics

Choose the illustration type according to the project:

- mobile-first products → phone mockup

- web or SaaS products → laptop / desktop mockup

- data / process-heavy products → chart, diagram or dashboard-style graphic

- public service / platform projects → interface mockup or contextual graphic

Important requirements:

- Each project visual must be easy to replace later without changing the layout.

- Treat each visual as a modular image slot / media component.

- Keep a consistent layout structure across all project banners.

- Use strong visual hierarchy, but do not let the illustration overpower the text.

- The placeholders should look polished and intentional, not generic empty boxes.

- Later, Jay will provide final PNG images for each project.

- The design must make it very easy to replace each provisional illustration with a final PNG using a future prompt, without redesigning the section.
